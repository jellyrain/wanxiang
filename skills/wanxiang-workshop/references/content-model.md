# 资料归属、字段用途与维护方式

本说明以万象工坊 0.1.2 的功能为准；调用前仍须查询正在运行实例的接口契约。旧版没有新接口时说明需要升级，不改塞世界档案。接口能接受一段文字，不代表这段文字适合放在那里。世界档案不是其他模块缺失时的默认存放位置。

## 写入前先判断

每次保存创作内容前，在内部核对：这是什么资料、属于哪个作品/世界、已有哪份记录、应更新哪个字段、哪些对象需要关联。常规保存不必把这张映射表发给用户审批。

- 先按语义分配模块，再构造接口参数。用户已确定的归档方式优先；只有影响内容归属且无法从已有资料确定的歧义才询问。
- 区分世界内的事实/规则、作品叙事、人物状态、创作备忘、外部素材。不要以原文件章节、聊天轮次或保存日期代替这些区别。
- 找到同一对象或规则的现有记录时，维护其当前内容和稳定编号。不要因一次新讨论就创建同义条目或在正文末尾追加讨论日志。
- 已有专门字段或关联时优先使用；不同页面通过关联引用同一份资料，不复制多份正文分别维护。
- 当前软件不能表达用户要求的管理能力时，说明具体缺口。不要虚构模块、字段或自动行为，也不要擅自把整段内容塞进世界档案、章节备忘或素材说明。

## 每个模块负责什么

| 模块/项目 | 正确用途与维护单位 | 边界 |
| --- | --- | --- |
| 作品 | 一部小说或故事的身份、名称、所属世界；正文、大纲、计划按作品独立 | 不为每个设定或讨论分支新建作品。已有作品不能直接迁移所属世界 |
| 世界信息 | 世界名称与简短总览，说明故事发生的整体背景 | 世界简介不承接完整设定库；同一世界的多部作品共用人物与设定 |
| 创作概览 | 作品简介、类型、封面、创作阶段、目标字数；备忘保存当前创作提醒，待办保存可执行任务 | 不存世界规则全文、小说正文或聊天逐字稿；待办完成状态不是设定采用状态 |
| 角色基础档案 | 一个独立人物的姓名、简介、经历、基础能力与事实字段 | 不把同一人物的化名、变身或不同时期重复创建为新角色 |
| 人物身份 | 同一人物的公开/隐藏身份、化名、称号、组织与身份说明 | 组织名称文字不等于已有完整势力档案；身份不等于人物本体 |
| 人物形态 | 同一人物的外观、变化条件、代价、图片、能力与属性覆盖 | 不以形态保存另一人物，也不用于保存装备清单 |
| 人物阶段 | 人物在某一时期的身份、形态、能力与数值快照 | 当前物品持有、功法修习和地点关联不随阶段冻结； 区别于软件修改历史；修订既有阶段默认保留冻结内容，只有明确要求重新取当前资料才 recapture |
| 资料标签、数值模板、补充字段 | 标签用于检索分组；属性模板定义数值维度、单位和范围，人物填写数值 | 标签不代替正文和关联；未确定的数值留空，不虚构能力值。补充字段保存文字设定；资料配置按人物、物品、功法、地点分别设置默认模板与补充字段 |
| 世界档案分类 | 按内容性质组织设定，例如制度、种族、修炼体系等；沿用已有分类 | 不按“本轮讨论”“第八章资料”“已认可内容”分类；不为单个条目重复建分类 |
| 世界设定条目 | 世界通用规则、制度、种族、势力、修炼体系等，维护连贯的当前定义 | 单件装备、道具、具体功法、物理场地使用各自专库；不接收讨论流水、采用清单或开发进度 |
| 物品库 | 装备、道具、材料、消耗品的定义、品阶、效果、条件、代价；持有行维护人物、数量、持有/装备/消耗/失去状态与备注 | 一个物品定义可关联多个持有人；当前是按人物汇总的记录，没有逐件实例、装备槽或自动转手账本 |
| 功法库 | 一部功法的流派、条件、效果、代价、层级说明；修习行维护人物、进度、状态与备注 | 通用修炼体系仍属世界规则；进度为显式文字记录，不自动计算突破、数值或人物能力 |
| 地点库 | 区域、建筑、场地的完整定义、所属区域、环境布局、进入条件，关联人物和地图标记 | 不要求先有地图；物理地点与剧情中的一场戏分开；不把历史事件累积为地点正文 |
| 关系图谱 | 人物之间的关系类型、方向、说明和适用阶段 | 当前只支持人物关系，不把装备、地点或功法伪装成人物节点；通用文字关联不等于专用管理逻辑 |
| 地图 | 空间布局、地图背景、地形、地点坐标与探索/剧情节点 | 地图节点控制揭示顺序，不是编辑版本；地图说明不代替世界设定全文 |
| 地图地点 | 一个地图上的位置标记，保存名称、类别、简述、图片、坐标、解锁节点及关联人物/设定 | 详细背景在地点库保存并关联该地图标记；点击“保存地图”会同时保存画布修改；“暂存到画布”仍须稍后保存地图 |
| 历史年表 | 世界内的年代与事件，记录何时发生什么、经过与影响，并关联人物阶段、地点、设定 | 不是 AI 操作日志或创作进度表；世界内时间不等于现实保存日期 |
| 作品大纲、分卷 | 作品的故事发展规划、分卷梗概与阅读目录 | 不存完整世界规则库；叙事顺序可以不同于世界年代顺序 |
| 章节 | 具体章节的名称、正文、梗概、创作备忘与出场/事件关联 | 正文放实际叙事，备忘放本章待改处、伏笔与写作提醒；不以章节临时安置未分类资料 |
| 素材画廊 | 图片原件及名称、分类、标签、用途说明、来源、生成提示词/制作参数 | 图片描述不代替人物或设定的当前档案；图片的制作记录可保留，不能混入无关创作讨论 |
| 作品设置 | 新建与选择作品/世界，修改名称和世界简介、编辑作品简介与计划、管理归档等 | 是作品与世界的管理入口，不是另一个内容库 |
| 软件设置 | 软件运行、连接、外观、更新、关于；提供历史、导入导出、备份等工具入口 | 软件问题进入项目使用问题记录，不写入创作资料；设置不是故事设定 |

## 世界条目的字段分工

| 字段 | 应保存的内容 |
| --- | --- |
| 名称、别名 | 对象或规则自身的名称与称呼，不用文件章节号或“本轮提案”命名 |
| 摘要 | 简要说明这是什么、为何重要，帮助用户在列表中识别 |
| 正文 | 一份完整连贯的当前设定或当前草案；必要时用小标题组织，不能持续堆叠旧方案和新讨论 |
| 关键字段 | 已知且适合单独查阅的归属、条件、层级、限制等事实；不把全文切碎充数，不虚构缺失值 |
| 待讨论 | 该条目尚未决定的问题、冲突或候选方向；不放全作品的待办和聊天记录 |
| 来源 | 原文件、参考出处或链接；不塞入采用状态说明和修改流水 |
| 状态 | 草稿/待讨论/已采用等软件状态，按实际确认程度设置；保存成功不等于用户采用 |
| 关联 | 用已有稳定编号连接人物或其他设定，并写清关系含义；不用“见第八节”替代对象关联 |
| 图片 | 与本条目相关的视觉资料，引用素材编号，不重复上传已有图片 |

这些分工同样用于理解其他模块的相似字段，但不能假定它们具备同样的状态枚举或字段：以当前契约为准。人物“经历”、年表“事件经过”和章节“正文”分别服务人物概况、世界事实与实际叙事，不能只因都是长文本就互换位置。

## 装备、道具、功法、场地的边界

0.1.2 已提供三个独立资料库和对应 API，详细保存方式见 [catalogs.md](catalogs.md)。先区分定义、当前状态、故事事件与叙事。

- 装备、道具、材料、消耗品统一进物品库，按世界内可编辑的 categoryId 分类；定义与当前持有人在同一物品中维护，不新增世界分类充当物品库。
- 具体功法进功法库；人物掌握进度和状态放 practitioners，人物能力栏只写此人物的能力概况。某一体系的通用境界、运行规则仍进世界档案，并用 entryIds 关联。
- 物理场地进地点库。坐标、解锁节点和地图标记留在地图探索；在已保存的地图标记上选择地点库资料，关联存于 positions 的 mapId/locationId。角色和世界条目也从各自页面选择三库资料，使用 saveCatalogLink 修改单条关联；三库编辑页专注定义，避免复制两份完整地点正文。
- 获得、转手、消耗、传承、突破、地点毁损等故事经过按任务需要记入历史年表；实际叙事放章节。不会因为修改当前状态就自动生成事件，不能向用户宣称已生成。
- 当前版本按人物汇总物品数量和状态，不提供逐件实例、同人物同物品分仓、装备槽位、自动消耗或转移事务。功法层级和修习进度为文字，不提供自动升级、数值计算。人物阶段不冻结三库关联；历史版本保存在对应资料中。
- 旧世界条目保留原位。只有用户要求整理/迁移时才核对旧条目、关联、来源和采用状态，形成明确映射后逐项处理；不要在新库重复复制后直接删原条目。跨接口迁移不是整体事务，失败时先核对成功部分。

## 更新现有资料与处理讨论

1. 先读取目标、关联对象与版本，识别本次用户已确认的内容、仍在讨论的内容，以及应保留的旧信息。
2. 以内容为单位整合当前记录。同一规则的新结论更新对应段落和字段；修订痕迹交给版本历史，不在正文末尾追加“某月某日第几轮补充”。
3. 整条仍是提案时保留草稿/待讨论状态；局部未决内容放适合的待讨论字段。已采用正文不得悄悄混入未确认的新事实，也不因一个局部问题将整份已采用内容降级。
4. 创作任务写入对应作品待办；本章写作提醒放章节备忘。尚未要求保存的讨论留在对话中。用户要求完整保存原始讨论、但当前没有合适载体时，说明缺口，不能用其他大文本字段兜底。
5. 文档导入先按对象/规则/事件/叙事识别内容，再决定落点；“第八节”“第一轮”不是自动拆条依据。全文保真导入章节仅适用于用户确实要导入正文的任务。
6. 稳定编号和真实关联优先。关键字段和关联不是每条必须凑齐的形式要求，但有明确关系时不能只把它埋在正文里；不为补齐字段编造设定。

## 保存后的验收与告知

读回校验内容、版本、状态和关联，再检查用户能否找到并理解这份资料：当前正文是否连贯、待定内容是否清楚、列表摘要是否能识别对象、引用是否能定位真实目标。涉及渲染或入口问题时再检查对应界面，不要求每次普通保存都操作窗口。

向用户报告具体位置和修改，例如“世界档案 → 修炼体系 → 某条规则：整合了成立条件，补充了相关人物关联”。不要只报告“已保存”或仅给数据库编号。没有完成的字段、关联或迁移如实说明。

| 情形 | 应采取的处理 |
| --- | --- |
| 一份文档有多节设定与开发备注 | 按设定对象整理，备注按用途分流；不机械建同数量条目 |
| 再次讨论同一条规则 | 整合当前正文/字段与待讨论项，保留旧历史；不在末尾堆一轮新日志 |
| 同一人物换化名、变身、进入新时期 | 分别判断身份、形态、阶段；不默认新建人物 |
| 记录小说中某次战争 | 年表保存事件；章节保存叙事；现实创作日期不能代替故事时间 |
| 保存一张图的生成参数 | 素材的提示词/制作记录字段，而不是世界档案 |
| 要求记录物品数量和装备状态 | 物品库 holders；若进一步要求槽位、逐件实例或自动流转，明确这些能力尚未实现 |

## 归档、历史与备份分别负责什么

- 归档/停用：从日常使用中收起，按模块规则保留内容和关联，可恢复；不是纠正错误分类的代替操作。
- 修改历史：已保存资料的旧版本与回退；不是故事内的历史年表，也不是人物阶段。
- 永久删除：移除明确选定的对象，先预览范围与引用；按 deletion.md 操作，不把用户的归档请求改成删除。
- 导入导出：资料包转移/交换，或用户指定的正文导入导出；按 transfer.md 校验范围，不把任意文档都导成章节。
- 备份恢复：保存或恢复资料库状态，按 backups.md 操作；不会因整理内容而自动建立全量备份。

使用中发现助手误操作、用法问题或软件异常，按项目 AGENTS.md 更新使用问题记录，同一问题补充原条目。明确区分已证实的问题、功能缺口和待核实现象；留档不自动授权修软件、改技能或清理已有资料。
