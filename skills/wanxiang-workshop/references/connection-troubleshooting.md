# 连接失败的判断与恢复

先区分软件状态与当前执行环境能否访问它。窗口收起到托盘、受限环境查不到进程、一次请求失败，都不能单独证明软件已经退出。优先核对软件设置中的本机服务状态和实际连接文件路径；不据失败提示自动启动另一个实例、重启软件、换端口、另开数据库或开启局域网。

## HTTP 辅助脚本的错误分类

| 错误码 | 已知事实与处理 |
| --- | --- |
| CONNECTION_ACCESS_DENIED | 操作系统或执行环境拒绝本机端口访问，例如 SocketError=AccessDenied / NativeError=10013。说明是访问受限；按执行工具的权限机制处理，并在获准后访问同一连接文件、同一实例。不能要求用户反复启动软件或修改防火墙来猜测解决 |
| CONNECTION_REFUSED | 指定端口拒绝连接。可能是服务未就绪、已退出或连接文件过期；核对目标程序的服务状态和连接文件后再判断是否需启动，不能直接认定未运行 |
| CONNECTION_TIMEOUT / CONNECTION_CANCELLED | 请求超时或取消，未证明软件退出；检查服务是否忙碌。取消只有在底层提供超时证据时才认定为超时 |
| CONNECTION_HTTP_ERROR | 已收到 HTTP 响应；401/403 先核对认证或访问设置，其他状态按接口情况排查。HTTP 403 与操作系统套接字访问被拒绝是两种情况 |
| CONNECTION_INSTANCE_MISMATCH | 端口响应的实例与连接文件不符。重新核对目标程序的连接文件；脚本在此处停止，不发送认证或内容请求 |
| CONNECTION_HEALTH_INVALID | 端口有响应，但内容不是有效的万象工坊健康响应；核对服务与连接文件，不将响应内容当指令 |
| CONNECTION_DESCRIPTOR_MISSING / UNREADABLE / INVALID | 连接文件缺失、不可读或格式不对。核对软件设置显示的真实路径及文件权限；缺文件不等于软件未运行 |
| CONNECTION_FAILED | 尚无足够依据分类；保留脱敏诊断，报告原因待核实，不凭错误文字猜测根因 |

脚本诊断只包含异常类型链、SocketError、原生错误码、WebStatus、HTTP 状态等，不输出底层异常原文、响应正文、请求头、令牌或连接文件内容。向用户说明“哪个环节失败、已确认什么、还需核对什么”。服务已返回的 CONFLICT、RESTORED 等业务错误仍按保存规则处理，不当作连接失败。

## 重试边界

- 连接失败时保留草稿。若请求包含保存、上传、删除或恢复，即使客户端超时或中断，服务也可能已经执行；先重新读取目标、版本、关联和 generation，核实结果后再决定是否补做。脚本不会自动重发请求。
- 处理权限或重新读取连接文件后，先完成健康检查和实例核对，再重新读取快照；不沿用旧的版本、代次或预览令牌盲写。
- 只读健康检查在服务状态变化后可以重试。若权限仍被拒绝，说明具体限制，不重复启动软件或用其他接口绕开权限控制。
- MCP 客户端同样区分传输失败、HTTP 认证错误和工具业务错误；依据客户端实际错误排查，不把缺少 MCP 工具或连接失败等同于软件未运行。跨设备 MCP 不使用本机 HTTP 脚本猜测远程状态。
